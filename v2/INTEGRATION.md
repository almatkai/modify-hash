## Process contract

Use the pinned SDK's hello/initialize/session.open/session.call/session.dispose/
shutdown protocol. Send canonical absolute package/data/temp paths and grant
only `selection.read`. The process never requests selection at open. After an
explicit selection action it requests `host.selection.read {kind:"files"}`;
reply with an absolute string array or a real reverse-RPC error. Do not coerce
null, bool or unknown objects to success. SDK disposal and cancellation require
normal process-generation and request ownership checks; never auto-replay an
effect request after timeout, cancellation or reconnect.

Selection completion does not overwrite fields or increment `_draftRevision`.
The request first adopts its current complete client snapshot, then
returns `Form.props.selectionCandidate` with the requesting action ID, its
client revision, JSON paths, and a one-use acceptance action ID. The renderer
records the requesting action/revision before dispatch, invalidates that owner
on every local field event (including A/B/A and invalid text), and admits a
matching candidate only while that exact owner is still pending. Admission
changes only `paths`, preserves every preference, increments the client revision,
and sends the full snapshot to the candidate action. The process consumes the
candidate before validation, requires exactly its next revision and expected
paths/preferences, and only then issues a fresh submit token. Newer field or
selection actions invalidate old candidates. Replayed acceptance is inert.
No confirmation UI or new SDK API is involved. A failed/canceled selection keeps
the draft editable and permits a fresh deliberate selection; an old effect token
never becomes current again. Actual request cancellation and late reverse replies
are exercised through the compiled SDK process.

The process opens files itself only after an explicit submitted action; host
grants are not an OS filesystem sandbox. Temp staging is always in the output
filesystem. The host's extension temp path is not assumed to share a volume.
No clipboard, shell, settings, paste, hide, notification or tray grant is needed.
There is no compiled-in Tauri domain registration, service restart, schema edit,
migration, background registration, SDK mutation, or new host-only feature API.
